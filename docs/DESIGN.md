版本：0.1（草案）
日期：2026-08-17

## 1. 项目概述

### 1.1 定位

NSAT（Natural-language Structured And Translated）是一门**中间描述语言**，不是最终可执行语言。

- 人用「自然语言 + 少量结构化规则」描述程序逻辑，写成 `.nsat` 文件。
- 编译器将 `.nsat` 文件交给用户配置的 AI。
- AI 严格依据人类逻辑翻译成目标语言（如 Python/Go/Rust），并返回两份产物：
  1. **补全后的 `.nsat` 文件**（供人类检查与继续修改，作为「真源」）
  2. **目标语言代码文件**（用于临时测试运行）
- 人与 AI 反复迭代，直到测试通过、程序完成。
- 最终编译阶段：所有 `.nsat` 文件经 AI 翻译为目标语言，再调用目标语言编译器产出最终程序。

### 1.2 核心原则

1. **人类写逻辑，AI 写代码。** 人类不直接面对目标语言语法。
2. **逻辑错误要过问人类。** AI 发现可疑逻辑错误时，默认必须征询用户（可配置为自动忽略）。
3. **测试用目标代码，维护用 NSAT。** 临时测试运行 AI 产出的目标语言文件；修复问题改的是 `.nsat`，不是目标代码。
4. **共同规则本地校验。** 缩进 / 冒号 / `[]` / `//` 等结构化规则由编译器本地离线校验，不消耗 AI。

### 1.3 技术栈

- 编译器本体：**Python 3.10+**
- 核心依赖：`requests`（或 `httpx`）用于调用 AI
- **UI 依赖**：`PySide6`（Qt6 for Python），桌面一体化界面（可选安装，`nsat install-ui`）
- 目标语言运行/编译：调用系统命令（`python`、`go`、`cargo` 等），可在配置中覆盖
- **分层架构**：核心逻辑（解析/配置/AI/运行/流程）是纯 Python 库，**CLI 与 GUI 只做外壳**，都通过 `nsat/api.py` 复用同一套核心，保证行为一致

## 3. NSAT 语言规范

> 规则会持续补充，本文件是「已确认规则」的权威记录。新增规则在 §10 登记。

### 3.1 文件格式

- 后缀：`.nsat`，文本文件，UTF-8 编码。
- 行分隔符：`\n` 或 `\r\n` 均可，解析时统一归一化。

### 3.2 目标语言声明（第一行，强制）

**文件的第一行必须是目标语言声明行。** 这是编译读取的第一条元信息。

- 内容为任意能表达编译意向的自然语言，例如：
  - `我想编译成Python`
  - `目标语言：Go`
  - `target: python`
  - `用 Rust 写`
- 该行**不得**以 `//` 开头（`//` 会被当作注释而无法识别声明）。
- 若第一行为**空白**（空行 / 只含空格），编译器在 `run`/`build` 开始时**交互式询问用户选择目标语言**，用户选定后再继续编译。**不由 AI 私自决定。**
- 第一行非空白时，编译器用**关键词匹配**在 `targets` 注册的语言名（含同义词，如 Python/py、Go/golang）中识别目标语言：
  - **唯一命中** → 直接使用，无需询问；
  - **无法识别或歧义** → 交互式询问用户确认。

```nsat
// 合法：关键词匹配直接命中 python
我想把这个文件编译成 Python

// 合法：空白，运行时交互式询问用户选择目标语言
（空白行）

// 非法（无法识别声明）
// 这是一个注释
import something
```

### 3.3 缩进（代码块界定）

- 与 Python 一致：以**缩进层级**界定代码块归属。
- 同一文件内缩进必须一致：要么全部使用 4 个空格，要么全部使用 Tab，**禁止混用**（本地校验会报错）。
- 缩进仅由代码行构成（块的开头行不缩进）。注释行不参与缩进层级计算，但嵌套块内的注释需要缩进以保持可读性。

```
循环 [i] 从 [1] 到 [10]：
    输出 [i]
    如果 [i] 是偶数：
        输出 这是一个偶数
    // 这行注释属于外层循环
输出 结束
```

### 3.4 冒号（块起始标记）

- 与 Python 一致：需要块体的语句（循环、判断、函数、类、with 等）以**冒号结尾**。
- 半角 `:` 与全角 `：` 均视为冒号，本地校验归一化为半角。
- 冒号行之后，**下一行必须缩进**；否则本地校验报错「冒号后缺少缩进块」。

示例（自然语言 + 冒号）：

```
循环 [i] 从 [0] 到 [n-1]：
    如果 [arr[i]] 大于 [max]：
        将 [max] 设为 [arr[i]]
    否则：
        跳过
```

### 3.5 专有名词 `[]`（变量 / 函数 / 模块标记）

- 所有**不可被 AI 当作普通自然语言推断的名字**必须用方括号 `[]` 括起：变量名、函数名、类名、模块/包名、常量名、文件路径等。
- 目的：让 AI 明确区分「这是要传给目标语言的标识符」与「普通的自然语言措辞」，防止误判。
- 标识符内容由用户自定，AI 负责转换为目标语言合法命名（如 `[我的计数]` → `my_count` 或 `my_cnt`，并在补全后的 NSAT 中保留 `[我的计数]`）。

```nsat
将 [sum] 初始化为 0
循环 [i] 从 [1] 到 [100]：
    将 [sum] 加上 [i]
调用函数 [compute_total] 传入 [data]
```

- **嵌套注意事项**：`[` 与 `]` 必须配对；`[]` 内不得出现另一个 `[`。若确实需要表达「数组下标」这类复合引用，用一条自然语言描述其含义，让 AI 决定如何在目标语言中表达，例如：`取 [arr] 中第 [i] 个元素`。

### 3.6 注释 `//`

- 一行中出现的 `//` 为行注释符：**从 `//` 起到行尾的全部内容视为注释，不参与编译、不发给 AI 之前参与本地校验的语义**（但注释仍会保留在补全后的 NSAT 提交给 AI，供 AI 理解意图）。
- 样例：

```nsat
// 这是整行注释
将 [x] 加 1 // 这是行尾注释
```

- 注意事项：
  - `//` 出现在 `[]` 内部时不算注释（例如路径 `[http://example.com]`），本地解析需跳过方括号内容。
  - 第一行声明行不允许使用 `//`（见 3.2）。

### 3.7 本地校验规则汇总（不消耗 AI）

| 规则 | 说明 | 违反时处理 |
| --- | --- | --- |
| 头部声明 | 第一行必须存在（可为空白） | 报错并提示 |
| 缩进一致 | 空格/Tab 不混用，缩进层级合法 | 报错 |
| 冒号块 | 冒号行后必须有缩进块 | 报错 |
| 方括号配对 | `[` `]` 成对，不嵌套 | 报错 |
| 注释合法 | `//` 位置符合 3.6 约束 | 报错 |

本地校验不通过的 `.nsat` 文件**不会**进入 AI 翻译阶段。

### 3.8 语义层（AI 理解层）

本地不解析自然语言语义。除 3.3–3.7 的机械规则外，其余一切语义都交给 AI：变量绑定、数据类型、函数调用、模块导入、错误处理等，全部由 AI 依据上下文与用户意图推断并翻译。

## 4. AI 抽象层

### 4.1 支持的提供商

| provider | 说明 |
| --- | --- |
| `deepseek` | DeepSeek，API 兼容 OpenAI 格式 |
| `openai` | OpenAI GPT |
| `anthropic` | Anthropic Claude |
| `custom` | 任意 OpenAI 兼容接口（Ollama、vLLM、国内中转等），通过 `base_url` 指定 |

实现基于统一基类 `AIProvider`（`nsat/ai/base.py`）：

```python
class AIProvider:
    def complete(self, messages: list[dict], *, temperature: float = 0.2) -> str: ...
    # 子类各自实现 HTTP 调用与鉴权
```

### 4.1.1 原生工具调用（function calling）

符合 vibe-code 惯例：AI 不只输出文本，还能**主动调用工具**（读文件、建文件、改文件等）。

- OpenAI 兼容接口（`openai`、`deepseek`、`custom`）：走 `tools` / `tool_calls` 参数 + `role="tool"` 消息回填。
- Anthropic：走 `tools` 参数 + `tool_use` / `tool_result` 块。
- 能力探测：首次请求带 `tools`，若接口报 `unsupported tools` 或返回非预期结构，则自动降级为 **提示词协议**（见 4.3 `needs_files`），并将该 provider 标记为 `tools_available=False`，后续不再附 tools 参数。

### 4.2 请求构造

每次迭代向 AI 发送：

1. **系统提示词**：固定描述 NSAT 规则、返回信封协议、翻译要求（严格遵循用户逻辑、不得擅自改变逻辑）。
2. **用户提示词**：
   - **目标语言**：编译开始前已确定（首行关键词匹配或用户选择），写入提示词，要求 AI 严格翻译且不得更改目标语言。
   - 当前 `.nsat` 内容（补全版或用户修改版）
   - **相关文件内容**：当前文件涉及的其他文件，按「文件间注入」规则（4.7）打包发送。
   - 历史会话（可选择传入前几轮的 NL + 目标代码 + 运行报错，SDK 内实现对话上下文）
   - 模式说明：本次是「首次翻译」还是「修复迭代」；若是修复，附上上次运行时的错误输出。

### 4.3 返回信封协议

AI 单次返回一个 **JSON 信封**，编译器据此拆分产物：

```json
{
  "nsat": "<补全后的完整 .nsat 文本>",
  "target_code": "<目标语言源代码>",
  "logic_issues": [
    {
      "line": 6,
      "concern": "循环边界疑似应为 n-1 而非 n，可能越界",
      "suggestion": "将 [i] 改为从 0 到 [n-1]",
      "severity": "warning"
    }
  ],
  "needs_files": [],
  "notes": "可选的补充说明"
}
```

- `nsat` 与 `target_code` 均为字符串（内部可能包含换行、引号，编译器按 JSON 解析，无需额外转义规则）。
- `logic_issues` 可空数组。
- `needs_files`：AI 翻译过程中发现还需要未提供的文件时填写（如 `["utils.nsat", "data.csv"]`）。编译器收到后**询问用户是否授权提供**：提供 → 注入文件后重跑本轮；不提供 → 让 AI 忽略并继续。
- 解析失败（AI 输出非合法 JSON）时：**补发一次「请严格输出 JSON」的重试**；仍失败则报错中止。

### 4.4 逻辑错误处理策略

AI 在翻译时发现的用户逻辑可疑点，按全局配置 `logic_errors.mode` 处理：

| mode | 行为 |
| --- | --- |
| `ask`（默认） | 列出所有 `logic_issues`，询问用户：**A. 采用 AI 方案 / B. 自行修改 / C. 忽略** |
| `ignore` | 静默忽略所有可疑逻辑错误，直接按 AI 原样翻译继续 |
| `auto_fix` | 自动选择 AI 建议方案，但把改动记录在报告里供用户查阅 |

- 采用 AI 方案 → 以 AI 返回的 `nsat`（或 `suggestion` 应用后的版本）作为新源文件，进入下一轮。
- 自行修改 → 打开编辑器（或提示用户改完后保存），改的是 `.nsat`。
- 忽略 → 以 AI 当前返回的 `nsat` 继续。
- 实用建议：迭代接近通过时设为 `ignore` 或 `auto_fix` 可减少打扰。

### 4.5 工具调用层（文件操作，Vibe Code 规范）

仿照 vibe-coding 代理（如 opencode / Cursor）的工具体系，给 AI 提供文件操作能力。

| 工具 | 能力 | 需要同意的操作 | 实现 |
| --- | --- | --- | --- |
| `read_file(path)` | 读取文件内容 | 访问 | `tools/file_tools.py` |
| `list_dir(path)` | 列出目录（递归可选） | 访问 | 同上 |
| `write_file(path, content)` | 新建 / 整体覆盖 | 创建 | 同上 |
| `edit_file(path, replacements)` | 按块精准修改（search/replace 列表） | 修改 | 同上 |
| `delete_file(path)` | 删除本地文件 | 删除 | 同上 |
| `run_command(cmd, cwd?)` | 在项目内运行命令 | 运行 | `tools/command.py`，默认关闭 |

约束：

- 工具**不能**越界访问 `nsatconfig.json`、`.git`、密钥文件之外的敏感文件——命中敏感路径时**强制拒绝**，无论权限配置如何（白名单之外即算敏感：`**/nsatconfig.json`、`**/.ssh/**`、`**/*.pem` 等）。
- 工具的「当前工作目录」固定为项目根目录，路径参数允许相对路径（解析到项目根）。

### 4.6 权限系统（询问用户同意）

对「创建（写）、修改（编辑）、访问（读/列目录）、删除」四类外部文件操作，默认**逐次询问用户**，符合 vibe-code 权限规范。

配置决定交互策略（`permissions.mode`）：

| mode | 行为 |
| --- | --- |
| `ask`（默认） | 每次操作弹确认：允许本次 / 拒绝本次 / 记住选择（本次会话内记住） |
| `allow_all` | 全部同意，不再询问（即用户勾选的「全部同意」） |
| `deny_all` | 全部拒绝；AI 对文件的写/删会被跳过并提示用户 |

- CLI 下用行内确认（`y/n/a(记住允许)/r(记住拒绝)`）；GUI 下用对话框，可勾选「本会话内记住」。
- 敏感路径即使 `allow_all` 也强制拒绝（见 4.5）。
- 工具调度器统一走 `permissions.py`，CLI 与 GUI 通过 `permission_ui.py` 提供各自的询问实现，核心逻辑不感知交互载体。

### 4.7 文件间注入（涉及文件全量发给 AI）

当 `.nsat` 文件涉及其他文件时，把这些文件**内容一并注入** AI 的 prompt，让 AI 全知地翻译，而不是半猜。

两条渠道：

1. **显式引用**：`.nsat` 中以 `[文件名.nsat]` 形式引用其他 NSAT 模块（见 §10 规则 6）。编译器静态扫描 `[*.nsat]` 记号，**递归**收集相关文件并注入。
2. **动态缺口**：AI 通过信封 `needs_files` 报告缺文件 → 询问用户 → 注入后重跑（见 4.3）。

注入格式（prompt 内分段标明来源，防止 AI 混淆边界）：

```
【相关文件：utils.nsat】
（原文内容……）
【相关文件：data/schema.csv】
（原文内容……）
```

默认注入当前 NSAT 直接/间接引用的全部相关文件；也可在配置 `context.follow_refs_depth` 限制递归深度。

## 5. 配置系统（`nsatconfig.json`，项目根目录）

```jsonc
{
  "ai": {
    "provider": "deepseek",          // deepseek | openai | anthropic | custom
    "model": "deepseek-chat",
    "api_key": "",                   // 也可用环境变量 NSAT_API_KEY
    "base_url": "",                  // custom 时必填；deepseek/openai 使用官方默认
    "temperature": 0.2,
    "max_tokens": 8192
  },
  "logic_errors": {
    "mode": "ask"                    // ask | ignore | auto_fix
  },
  "permissions": {
    "mode": "ask",                   // ask | allow_all | deny_all
    "enable_tools": true,            // 是否启用 AI 工具调用层（编辑器 AI 窗口始终有读权限）
    "allow_run_command": false       // 是否开放 run_command
  },
  "context": {
    "history_rounds": 4,             // 送入 AI 的历史迭代轮数，0 表示不送
    "follow_refs_depth": 3           // 文件间注入递归深度，0 表示仅当前文件
  },
  "targets": {
    "python":  { "run": ["python"], "build": ["python", "-m", "py_compile"] },
    "go":      { "run": ["go", "run"], "build": ["go", "build"] },
    "rust":    { "run": ["cargo", "run"], "build": ["cargo", "build"] }
  },
  "output": {
    "dir": "out"                     // 临时测试与最终产物的输出目录
  }
}
```

- 配置可被 CLI 参数覆盖（如 `--provider`、`--model`）。
- `NSAT_API_KEY` 环境变量优先于配置文件中的明文 `api_key`（避免密钥入库）。
- 未安装的目标语言编译器在调用时报明确错误（如「找不到 python，请安装或修改 targets 配置」）。

## 6. CLI 命令

| 命令 | 作用 |
| --- | --- |
| `nsat init` | 生成 `nsatconfig.json`（交互式向导填写 AI 提供商等） |
| `nsat check <file.nsat>` | 仅本地语法校验（§3.7），不调 AI |
| `nsat run <file.nsat>` | 临时测试：本地校验 → AI 翻译 → 按 logic_errors 策略处理 → 运行目标代码 → 展示结果；可交互反复迭代 |
| `nsat build <entry.nsat> -o <dir>` | 最终编译：编译项目内全部 `.nsat`，再调用目标语言编译器，产出最终程序 |
| `nsat review <file.nsat>` | 只请求 AI 的 `logic_issues` 供查看，不产出代码 |
| `nsat ui` | 启动桌面界面（首次运行若未安装 PySide6，提示 `nsat install-ui`） |
| `nsat install-ui` | 安装 GUI 依赖（`pip install PySide6`） |

常用示例：

```
nsat init
nsat check hello.nsat
nsat run examples/fib.nsat            # 进入迭代模式，可输入继续/修改/退出
nsat build src/main.nsat -o dist
nsat ui                               # 打开桌面一体化界面
```

## 7. 工作流程

### 7.1 临时测试循环（`nsat run`）

```
用户写 main.nsat
    │
    ▼
┌─────────────────────────────┐
│ 1. 本地校验（parser.py）      │──失败──▶ 报错并提示行号，用户修改
└─────────────────────────────┘
    │ 通过
    ▼
┌─────────────────────────────┐
│ 1.5 确定目标语言             │
│     读首行→关键词匹配         │
│     空白/无法识别→询问用户选择 │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│ 1.6 文件间注入               │
│     扫描 [*.nsat] 引用        │
│     递归收集相关文件→打包进 prompt
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│ 2. 调用 AI（provider + prompts）
│    返回 JSON 信封             │
│    needs_files 非空 ──▶ 询问用户
│        提供→注入后重跑 / 不提供→忽略
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│ 3. 逻辑错误处理（按 mode）    │── ask ──▶ 询问：采用/修改/忽略
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│ 4. 写入两产物                 │
│   out/main.nsat（补全版）    │
│   out/main.py （目标代码）    │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│ 5. 调用目标语言运行器          │
│   python out/main.py         │
└─────────────────────────────┘
    │
    ▼
   成功? ──是──▶ 展示结果，询问是否：
                  (a) 进入最终编译 / (b) 继续修改 / (c) 退出
    │
   否（报错/输入不符预期）
    ▼
用户打开 out/main.nsat 修改 / 用自然语言描述问题
        └────────────▶ 回到步骤 2（携带历史上下文与上次报错）
```

要点：

- **迭代的「真源」是 `.nsat`**：每次循环读的是 AI 补全版或用户改过的 `.nsat`，目标代码每次重新生成，不允许用户直接手改目标代码（除非配置 `allow_manual_target_edit` 临时开启，作为例外并警告）。
- 步骤 5 的「运行结果」包括：正常输出、退出码、stderr、运行时长、以及（可选）用户自定义的验收断言。
- 用户可以在迭代时用一句话描述新问题，例如值「现在程序输出是 0，但我期望 5，请修复 [compute_total]」——原样附带进下一轮 prompt。

### 7.2 最终编译（`nsat build`）

1. 收集项目内全部相关 `.nsat` 文件（由入口文件及 AI 报告中的引用关系确定，参考 §10 文件引用规则）。
2. 逐个调用 AI 翻译成目标语言，得到各模块目标代码。
3. 将产出文件写入 `out` 目录（保持扩展名与目标语言对应）。
4. 调用目标语言**编译器**（不是运行器）进行编译，产出最终程序：
   - Python → `py_compile` 校验编译
   - Go → `go build -o program`
   - Rust → `cargo build --release`
5. 报告最终产物路径与编译结果。

### 7.3 状态与产物留存

- 每轮迭代的产物都保留在 `out/round_N/` 下：`*.nsat`、`*.目标扩展名`、`run.log`、`nsat_report.json`（AI 原始信封）。
- 方便回溯「上一版为什么能跑、这一版改了什么」。

## 8. UI 桌面一体化界面（PySide6）

### 8.1 定位与原则

- 目标是让「创建 → 编辑 → 校验 → 测试 → 迭代 → 最终编译」全程在图形界面完成，无需手敲命令行。
- GUI **不实现任何业务逻辑**，只负责展示与交互；所有编译行为都调用 `nsat/api.py` 的核心 API，与命令行行为完全一致。
- 复杂任务（AI 调用、子进程编译/运行）放后台线程（QThread），主线程只做 UI，保证界面不卡死。

### 8.2 主窗口布局

```
┌────────────────────────────────────────────────────────────┐
│ 菜单栏：文件 / 编辑 / 运行 / AI 配置 / 视图 / 帮助            │
├──────────┬──────────────────────────────────┬───────────────┤
│          │                                  │  Ai 配置面板    │
│ 项目文件树 │        编辑器（tab 多开）           │  · 提供商/模型 │
│          │   行号 │ NSAT 语法高亮 │ 校验错误标记 │  · 逻辑错误策略 │
│          │                                  │  · 密钥(隐藏)  │
│          │                                  ├───────────────┤
│          │                                  │ AI 助手对话（tab）
│          │                                  │  · 项目级问答   │
│          │                                  │  · 工具调用/权限│
│          │                                  ├───────────────┤
│          │                                  │ 迭代历史列表    │
│          │                                  │  · 各轮产物     │
│          │                                  │  · 运行结果     │
├──────────┴──────────────────────────────────┴───────────────┤
│  底部：运行输出 / 校验结果 / 错误列表（可点击定位到行）          │
└────────────────────────────────────────────────────────────┘
```

### 8.3 功能清单

| 功能 | 说明 |
| --- | --- |
| 打开/新建/保存 | `.nsat` 文件，UTF-8；支持多标签页、最近打开列表 |
| 语法高亮 | 自定义 `QSyntaxHighlighter`：`[]` 内标识符、冒号行、`//` 注释、目标语言声明行分别着色 |
| 结构性编辑辅助 | 冒号行回车自动缩进、Tab/缩进增减、整块缩进、括号配对始终检测 |
| 实时/保存前校验 | 调用 `parser.py`，错误在行号栏红点标记；底部错误列表可点击跳转 |
| 目标语言识别 | 打开文件即按 §3.2 关键词匹配显示当前目标语言徽标；空白/未识别时提示选择 |
| 一键运行测试 | 触发 `run` 流程，进度状态栏提示「调用 AI → 写入产物 → 运行目标代码」，输出实时显示到底部面板 |
| 逻辑问题弹窗 | `ask` 模式下弹出 `logic_issues_dialog`，支持 采用/自行修改/忽略 三选一 |
| AI 配置 | `ai_config_dialog` 编辑并保存到 `nsatconfig.json`；密钥字段掩码显示，可读/写环境变量 `NSAT_API_KEY` |
| 迭代历史 | 右侧 `history_panel` 列出现有各轮（`out/round_N/`），一键对比 `*.nsat` 与目标代码，回看 `run.log` |
| 最终编译 | 工具栏「构建」按钮 → `build` 流程，产物目录可设置 |

### 8.4 交互细节

- **校验即反馈**：用户停止输入（防抖 300ms）后在后台线程重新校验，不打断编辑。
- **运行不阻塞**：`run_worker` 在后台执行，期间主界面仅锁定「运行」按钮；输出逐行 append 到面板。
- **ask 策略弹窗**：等同 CLI 的 A/B/C，但用对话框呈现，附每个问题的行号定位与建议预览。
- **文件监听**：被外部工具修改的文件给出重新加载提示。
- **深色/浅色主题**：跟随系统，可手动切换。

### 8.5 AI 助手窗口（项目级对话）

在右侧新增一个 **AI 对话面板**（可与历史面板折叠切换），承担一部分 NSAT 编译之外的「vibe code」职能：

- 用户可以向 AI 询问：
  - 整个项目应如何组织文件目录、模块怎么拆分；
  - 某个现有 `.nsat`/普通文件是干什么的；
  - 翻译某段逻辑时应该怎么写，或直接「帮我新建一个 `main.nsat` 完成 X」；
  - 查看项目文件树、让 AI 推荐引入哪些代码。
- 该窗口的 AI **默认开启工具调用**（§4.5），可以：
  - 读取任意项目文件（需权限）；
  - 新建/修改 `.nsat` 或辅助文件（需权限）；
  - 对创建、修改、访问、删除外部文件**逐次请求同意**，弹出许可对话框（可勾选「本会话内记住」，或用户已在配置里选 `allow_all` 则直接放行）；
- 对话与编译主流程**相互独立**：助手窗口写的文件即项目文件，主流程的 `run`/`build` 读取的是磁盘上的最新版本。
- 助手窗口谈话记录不进入编译上下文（除非用户把生成的文件保存为 `.nsat` 并从它开始运行）。

### 8.6 与 CLI 的关系

- `nsat ui` 是纯入口，等价于 `python -m nsat.ui`。
- 缺失 PySide6 时给出提示并建议 `nsat install-ui`，不阻塞 CLI 其他命令使用。

## 9. 目标语言编译/运行调用

- 通过 `runner.py` + `targets` 配置执行子进程。
- 输入：目标代码文件路径、入口文件、工作目录、超时。
- 输出：退出码、stdout、stderr，供展示与下一轮 prompt 使用。
- 运行器用 `subprocess.run(..., timeout=...)`，默认超时 30s，可在 CLI 用 `--timeout` 覆盖。

## 10. 已确认规则与待完善规则登记

**已确认（本文件 §3）：**
1. 首行目标语言声明（非空白→关键词匹配识别；空白/无法识别→询问用户选择，不由 AI 决定）
2. 缩进界定代码块（禁止空格/Tab 混用）
3. 循环/判断等块语句以冒号结尾
4. 专有名词 `[]` 标记
5. `//` 行注释（`[]` 内不算注释）
6. 文件间引用：以 `[文件名.nsat]` 形式引用其他 NSAT 模块，编译器递归收集并注入 AI 上下文（§4.7）；引用的文件缺失时询问用户或让 AI 忽略

**待完善（开放议题，后续补充到 §3）：**

- 函数 / 类如何用自然语言定义（`[函数名]` + 参数/返回描述）
- 多行注释 `/* ... */`
- 变量的数据类型声明（`[x] 是一个整数`）与类型校验
- 验收断言 / 测试用例用自然语言描述
- 作用域规则（缩进嵌套以外的语义作用域）
- AI 返回补全版 NSAT 的**体裁规范**（措辞风格、每条指令粒度、编号或列表形式等），将逐步在 §4.2 明确

## 11. 里程碑

1. **M1 最小可用**：`init` / `check` / `run`（仅 Python 目标），支持 OpenAI 兼容接口与 DeepSeek，`ask` 逻辑错误处理，文件间注入（`[文件.nsat]` 递归收集），`needs_files` 重跑，跑通 Hello World 与一个循环/判断示例。
2. **M2 迭代增强**：历史上下文、`auto_fix`/`ignore`、验收断言、超时与重试健壮性。
3. **M3 工具调用与权限**：原生 function calling（OpenAI/DeepSeek/custom + Anthropic 降级）、文件工具集、权限系统（ask/allow_all/deny_all + 敏感路径封锁）。可并行推进。
4. **M4 多语言**：Go / Rust 目标，`build` 最终编译全流程。
5. **M5 多文件工程**：文件引用完善、AI 补全版 NSAT 体裁规范、报告与产物回溯工具。
6. **M6 UI 桌面一体化**：编辑器 + 语法高亮 + 校验标记 + 一键运行 + AI 配置 + 逻辑问题弹窗 + 迭代历史面板 + **AI 助手窗口（含工具调用与权限弹窗）**。可并行于 M2–M5 推进，作为独立分支。
